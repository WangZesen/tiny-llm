## Authoring and preview

Markdown under `doc/` is authoritative. Results, Methods, Guides, Performance, and Archive map to website routes. Each article has YAML frontmatter with a `title`, optional `description`, and `archive: true` for historical reports. Use relative Markdown links so the source remains readable on GitHub. The build translates document, data, and configuration links for the `/tiny-llm/` website base.

Website code and its independent lockfile live in `site/`. Use Node 24 or newer:

```bash
npm --prefix site ci
npm --prefix site run build
npm --prefix site run dev
```

Open `http://127.0.0.1:4321/tiny-llm/`. Search is generated by the production build; use `npm --prefix site run preview` to check it. Math uses `$...$` and `$$...$$`, compiled with KaTeX. Unsupported notation fails the build.

Keep results articles concise. Use the explorer for full rankings and seed records. Explain protocol differences and limitations where they affect interpretation.

## Add or update a study

Add a reviewed record to [the study registry](../data/studies.json), including its stable ID, display name, source directory, worker count, scheme, clipping setting, preset link when applicable, and expected counts. Store audited source data under `doc/data/`.

The normalization code in `site/tools/data.ts` adapts the source format, checks means and sample SDs against individual runs, verifies seed groups and preset consistency, and produces build artifacts. A new incompatible format needs an explicit adapter. Overlapping analyses such as the beta99 slice must not become duplicate primary studies.

Generated website data and copied public assets are ignored by Git. Original study records and exported curve snapshots are committed. Preserve original JSON provenance paths and hashes; those describe historical execution even after relocation.

## Refresh recorded curves

Refreshing reads existing logs and resolved configurations. It launches no training or analysis. Run where the original artifacts are available:

```bash
npm --prefix site run data:refresh
# Or point at another copy:
npm --prefix site run data:refresh -- --runs-root /path/to/runs
npm --prefix site run data:check
```

The exporter matches recipes/seeds, verifies completed full validation, hashes metrics and result files, and saves recorded training/subset-validation points. Missing logs are listed in the coverage manifest. Review snapshots and coverage before committing. An incomplete source copy can reduce coverage, so refresh from the authoritative directory.

The initial publication contains 753 final results and curves for 726 runs. Restore the 27 missing logs and rerun the exporter to add them. Seed statistics combine only matching recorded token positions, without smoothing.

## Validation

```bash
npm --prefix site run check
npm --prefix site test
npm --prefix site run build
cd site
npx playwright install chromium
npm run test:browser
```

The build validates data and internal links, renders math, and generates local search. Browser checks cover filters, selection, curve views, URL restoration, downloads, missing data, mobile layout, and themes.

## GitHub Pages

Pull requests build and validate the site. Successful pushes to `main` publish at `https://wangzesen.github.io/tiny-llm/`. Manual dispatch on `main` is also supported. The repository's Pages source must be GitHub Actions; deployment uses the `github-pages` environment.

CI needs only the Node lockfile, committed documentation, data, and configuration files. It does not install the Python training environment or access GPUs, Slurm, checkpoints, or ignored logs. Build output is uploaded as a Pages artifact rather than committed to a deployment branch.

Historical reports are linked from the footer and excluded from default search. Adaptive-consensus PDFs are copied from their preserved bundle; their separate Typst build is not part of website deployment.
